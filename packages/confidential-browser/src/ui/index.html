    Registry source — read only
          
          
    Supports OCI/Docker gzip or uncompressed layers; zstd is currently unsupported. Your browser verifies the registry's HTTPS certificate, selects linux/amd64 and pins its manifest digest. The stack relays opaque encrypted connections; it cannot read source credentials or image layers. Redirects never receive registry login credentials.
    
          
    Optional registry login
            
            
            
            
            
    Only authorize a token-service hostname you independently trust. Your registry login may be sent there over browser-verified HTTPS.
    
          
    
          
    Separate key for an encrypted source image
            
            
    Optional for plaintext sources. Native CoCo encrypted layers need their 32-byte image key as 64 hex characters or standard base64. This key is separate from the registry login and the new destination image key.
    
            
            
            
    Only Nebula's PBKDF2-SHA256/AES-GCM recovery format is supported. Its password unlocks the source image key locally; it never replaces this stack's owner. There is no universal image password format.
    
          
    
          
        
    
        
    Image storage is managed by this stack. Your browser encrypts the image before sending its encrypted layers and public OCI metadata to that storage. No destination registry account is needed.
    
        
    Files needed by this stack
          
    New disk keys are generated in your browser. Only stacks using existing encrypted disks need a disk-key file.
    
          
    
        
    
        
        
    Use at least 12 characters. The encrypted backup contains your owner and encryption keys, not disk contents or your image archive. Keep the retained disks, original archive, latest backup and its password.
    
        
    
        
    Stack runtime settings
    
          
    Settings applied by this stack, including any explicit command or environment overrides.
    
          
    
          
    Exact application settings to approve
    These settings include command, arguments, environment, mounts, resources and network. Runtime attestation does not decide whether an application is suitable for your data.
    
        
    
        
        
        
    
        
      
    
      
    Plaintext image layers stay on your computer until the final guest decrypts them. Image and disk keys go directly to that verified guest's Trustee. The application receives its declared files and mounted storage, without the disk keys.

    Protection and limits
    Your browser, independently reviewed measurement references and verifier, and the verified guest software are trusted. This page's convenience checker cannot establish its own initial authenticity; compare and verify the browser certificate independently first. Administrators can deny service or claim first; that is detected before your image is uploaded. An enrolled VM replacement requires explicit recovery. There is no global singleton or disk rollback guarantee.
